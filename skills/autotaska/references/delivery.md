# Real implementation and delivery

## Implementation

Inspect actual source and selected engineering instructions before edits. Use the existing stack, domain boundaries, conventions and contract owners. Implement backend/data and client consumers together at accepted slice boundaries. Apply relevant validation, authorization, tenant/owner isolation, persistence and provider failure behavior.

Do not replace missing credentials/services with fabricated success. Isolated fixtures may support explicit test/design work; keep the real integration task open. Code generated in a conversation is proposed source until written/integrated into the actual repository and checked.

## Integration

Review returned artifacts/diffs and reconcile them with current user work and canonical contracts. Resolve conflicts deliberately; never blindly merge/cherry-pick based on a completion message. Changes to DTOs/schema/auth/startup must reach all affected consumers and verification records.

## Verification

Run project-appropriate builds/static checks and meaningful behavior tests. Inspect actual persistence after reload/new scope, unauthorized access, invalid input and failure handling when relevant. Inspect real browser/mobile behavior when supported. Verify requested RTL/LTR, responsiveness and themes only as part of the actual product scope.

Separate generated source, successful build, database checks, UI behavior, external providers and deployment. Retain exact evidence/failures. Rerun affected checks after repairs; do not repeat unchanged passing checks without a reason.

## Release and handoff

Prepare reproducible configuration and delivery instructions/artifacts. Use actual session authorization for publishing, external writes or production migrations; do not introduce repeated approval pauses for already authorized work. Never deploy merely because a release department exists.

Report implemented outcome, verification and concrete blockers concisely. Classify readiness claims as VERIFIED, NOT VERIFIED or BLOCKED BY ENVIRONMENT where useful. Give the canonical repository/project artifact and observed department links. A screenshot, passing build or generated file alone does not prove a complete app.
