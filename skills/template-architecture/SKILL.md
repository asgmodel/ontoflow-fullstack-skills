# معمارية Template

حوّل متطلبات المستخدم إلى مشروع مستقل يحافظ على معمارية Template. استخدم تعليمات Markdown والأصول المحلية دون الاعتماد على مزود AI بعينه. توافق الاستيراد التلقائي يختلف بين الأدوات؛ عند عدم وجود نظام Skills اطلب من الوكيل قراءة هذا الملف والمراجع ذات الصلة.

## ابدأ بالتحديد
1. اقرأ [خريطة المعمارية](references/architecture.md) و[حدود القالب](references/source-audit.md).
2. ميّز بين إنشاء مشروع فارغ، إضافة ميزة إلى مشروع قائم، أو إعادة تسمية. لا تنسخ القالب فوق مشروع قائم.
3. استخرج اسم المنتج ونطاق الميزة والبيانات والصلاحيات من الطلب. استخدم App.Server مؤقتًا عند غياب الاسم؛ لا تخترع متطلبات منتج.
4. حافظ على مشروع خلفية واحد؛ فصل الطبقات هنا بالمجلدات وليس مشاريع مستقلة. تبعيات الطبقات قواعد يجب مراجعتها حتى لو سمح المترجم بخلافها.

## أنشئ مشروعًا فارغًا
شغّل من أي مجلد باستخدام المسار الفعلي لهذه المهارة:
```sh
python <skill-dir>/scripts/scaffold.py --output <new-directory> --name MyProduct
```
يشترط عدم وجود الوجهة، ويتحقق من الاسم ويعيد تسمية الملفات والمراجع معًا. الاسم حرف لاتيني يليه أحرف أو أرقام فقط. لا يحتاج Python إلى حزم إضافية. عند عدم توفر تشغيل كود انسخ assets/blank-project يدويًا إلى وجهة جديدة وطبّق نفس الاستبدالات الواردة في السكربت.

القالب فارغ من وظائف الأعمال والمستخدمين والإشعارات والبيانات التجريبية. يحتوي بنية الخادم وواجهتين فارغتين وDbContext دون كيانات. لا تُضف تسجيل دخول أو AI أو خدمات دفع إلا عند طلبها. الإصدارات موروثة من الملف المصدر؛ تحقق من توافقها عند التنفيذ ولا تحدثها تلقائيًا.

## نفّذ الميزات
- استخدم template-backend للـDomain وحالات الاستخدام وEF وواجهات API والأمن والتكاملات. إن لم تتوفر المهارة: طبّق قواعد خريطة المعمارية هنا وافحص المصدر مباشرة.
- استخدم template-frontend للواجهات والتوجيه وعقود API وBlazor.
- استخدم template-verification للتحقق والتسليم.
- اقرأ [عقد التنفيذ](references/delivery.md) لتحديد ما يلزم تسليمه.
- نفّذ شريحة متكاملة: Domain → Application → Infrastructure → Controller → UI → الاختبار. لا تحول كل طبقة إلى خدمة مستقلة ولا تضف Express أو Firebase إلى ClientApp.
- احتفظ بقرارات المشروع الحالية والتصميم المعتمد. عند تعارض طلب المستخدم مع افتراض القالب، اتبع طلبه ووضّح أثر التغيير.

راجع [سجل المصدر](references/source-manifest.json) عند الحاجة إلى مطابقة مجلدات القالب مع الأرشيف الأصلي.

## أختم بالأدلة
أبلغ عن الملفات المتغيرة والنتائج الفعلية وحدود البيئة. نجاح إنشاء الملفات ليس نجاح تشغيل النظام. لا تدّعِ أن تسجيل الدخول أو قاعدة البيانات أو النشر يعمل دون اختباره.
